# AWESOME · AI-маркетолог

MVP для хакатона «Кибер 102». Go backend, Python Telegram transport, Vue 3 Mini App. Генерация текста работает через **аккаунт ChatGPT, подключённый в админке**, с помощью Codex CLI, без отдельного OpenAI API-ключа.

## Что реализовано

- Задачи на естественном языке в Telegram и в Mini App.
- Отдельные профили компаний, база знаний, история и каналы.
- В настройках компании — загрузка PDF, DOCX, TXT и MD до 50 МБ, импорт текста страницы сайта по ссылке, просмотр извлечённого текста и включение/отключение источников. Текст хранится отдельно от краткого описания и автоматически попадает в контекст генерации выбранной компании.
- Генерация текста с учётом компании и последних сообщений.
- Генерация полного изображения встроенным инструментом Codex по визуальным референсам выбранной компании. Композиция, текст, логотип и фотографии создаются вместе; фиксированной шапки/подвала нет.
- До 6 своих JPG/PNG (до 12 МБ каждый) через кабинет или альбомом в Telegram. Исходные фото передаются в image generation/edit, чтобы люди и событие естественно участвовали в общей композиции. Отдельного наложения фото поверх шаблона нет.
- Форматы 1:1 (1080×1080), 4:5 (1080×1350) и 16:9 (1440×810), выбираются до генерации и при доработке. В боте: /format_square, /format_portrait, /format_wide. При изменении только изображения текст сохраняется дословно.
- В Mini App есть «Диалог с AI»: очередь, текущий этап, время работы, вопросы AI и поле ответа. Ответ продолжает ту же задачу с сохранением фотографий, пропорций и настроек бренда. Несколько задач можно переключать в списке.
- Уточнения и ответы остаются в диалоге/истории; в материалы и публикации попадают только готовые посты. Уведомление об ожидающем ответе видно во всех разделах кабинета; переходить в бот не требуется.
- Редакционный профиль из брендбука 15.11.2023 и 13 предоставленных примеров: хук, короткие абзацы, тематические эмодзи, выделения, цитатные блоки и рубричные хештеги. Примеры используются для стиля; события, имена и даты из них не считаются новыми фактами.
- Пересылка поста боту сохраняет полный текст, оформление и custom emoji для активной компании. Данные и история компаний изолированы.
- Посты до 3800 символов отправляются целиком: короткие — подписью к картинке, длинные — изображением и отдельным форматированным сообщением.
- Настройки компании: отдельный логотип, до 8 примеров визуального стиля, пожелания к изображениям; они автоматически используются в следующих задачах. Можно заменить логотип или примеры только для одного поста.
- Выбор эмодзи: обычные, из пересланных референсов или любой доступный Telegram-пак по ссылке `t.me/addemoji/...` / имени. Набор проверяется и загружается через Telegram, его ID не зашиты в код. В режиме выбранного пака действует строгая проверка: неподдерживаемые эмодзи удаляются до сохранения текста, ручные правки тоже проверяются, а отправка не заменяет custom emoji стандартными.
- Одобрение, отклонение, доработка с комментарием и ручное редактирование. Режимы «Только текст», «Только изображение», «Текст и изображение». При изменении только текста изображение и его файл сохраняются, image generation не вызывается.
- Одобрение связано с версией. Любые правки отменяют согласование.
- Публикация в Telegram, ссылка на результат, задачи по расписанию.
- Ежедневная публикация в выбранное время; еженедельная — в выбранный день недели и время (МСК). Подготовка начинается за 15 минут, согласованный пост ждёт своего времени. Отправку проверяет отдельный таймер раз в секунду, независимо от длительности генерации. Время и день можно изменить в расписании; изменение времени отменяет прежнее одобрение. При пропущенном времени позднее одобрение переносит пост на ближайший свободный выпуск. После простоя более 30 секунд пропущенные одобренные посты также переносятся и требуют нового согласования.
- Демо-интервал 30 секунд, кнопки «Пауза / Включить» и общая остановка на главном экране. Пауза отменяет ещё не завершённые генерации этого расписания, готовые черновики сохраняются.
- Повторы Telegram-действий дедуплицируются по update_id; сбой доставки подтверждения не превращается в ложную ошибку выполненной доработки.
- Сохранение состояния после перезапуска и журнал событий.
- Проверка подписи Telegram initData, срока действия и доступа к компании.

## Быстрый локальный запуск

Требуются Go 1.23+, Node 22+, Python 3.10+, Codex CLI 0.168.0.

```bash
npm install -g @openai/codex@0.168.0
cp .env.example .env
# Заполните .env. INTERNAL_TOKEN — случайная строка минимум 32 символа.
# ADMIN_IDS — числовые Telegram ID, через запятую.
# Для локального кабинета можно задать LOCAL_ADMIN_TOKEN=<случайный секрет>.
./scripts/dev.sh
```

Кабинет: http://127.0.0.1:8080. Локальный вход работает только на loopback-хосте без forwarded-заголовков и при явно заданном LOCAL_ADMIN_TOKEN. Для Telegram нужен PUBLIC_URL с HTTPS. Бот при старте настраивает меню **«Открыть»** через setChatMenuButton.

Кнопка запуска приложения **в профиле бота** настраивается дополнительно владельцем через BotFather → /mybots → бот → Bot Settings → Configure Mini App → Enable Mini App. Укажите тот же PUBLIC_URL. Это отдельная настройка от меню «Открыть» в чате.

## Развёртывание на сервере

1. Установить Docker Engine и Compose plugin, открыть TCP 80/443 и SSH для администратора.
2. Скопировать проект, создать `.env`, задать DOMAIN и PUBLIC_URL. Домен должен указывать на IP сервера.
3. Собрать образ и запустить приложение:

```bash
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=50 backend bot
```

После запуска откройте ☰ → «Лимиты и доступы» → ChatGPT → «Войти в ChatGPT». Перейдите на страницу OpenAI и введите показанный одноразовый код. Caddy получает HTTPS-сертификат автоматически. Бот не публикует при отсутствии одобрения. Не запускайте одновременно две копии Telegram polling для одного токена.

Проверка: `curl https://<DOMAIN>/healthz`. Все /internal/* и /api/local-session закрыты публичным reverse proxy. На сервере LOCAL_ADMIN_TOKEN отключён.

## Сценарий демонстрации (5–7 минут)

1. Открыть @awesomesmm_ai → /start → «Открыть».
2. В разделе «Компания» заполнить факты, аудиторию и стиль; сохранить.
3. Отправить: «Подготовь пост-знакомство о нашей компании».
4. Получить текст и карточку; нажать «Доработать» и прислать комментарий.
5. Получить версию 2; убедиться, что старое одобрение не действует.
6. Одобрить новую версию; открыть ссылку на реальный пост в @awesome_smm.
7. Спросить: «Что мы только что опубликовали?» — ответ учитывает историю.
8. Добавить вторую компанию через интерфейс, задать отличающиеся факты.
9. Создать расписание на ближайшую минуту; показать автономное создание черновика.
10. Перезапустить backend; показать сохранённую историю и задачи.

## Материалы и сайт компании

Откройте «Компания → Материалы о компании». Документы PDF/DOCX/TXT/MD до 50 МБ сохраняются как отдельные источники. Для сайта вставьте адрес нужной страницы и нажмите «Загрузить информацию с сайта». Импортируется статический текст этой страницы, без исполнения JavaScript; другие разделы добавляются отдельными ссылками. Включённые источники автоматически используются в новых задачах этой компании. Переключатель «Учитывать» исключает источник без удаления документа. Извлечённый текст можно проверить в карточке источника.

Импорт ограничен 80 страницами PDF и 60 тысячами знаков на источник; в один запрос генерации входит до 100 тысяч знаков из активных источников. Сканированные документы без текстового слоя требуют OCR. Сайты должны быть публичными; внутренние IP, служебные сетевые адреса, URL с паролем и небезопасные перенаправления заблокированы. Исходные файлы хранятся в `/data/sources`, текст и настройки — в состоянии приложения, поэтому при переносе нужен весь том `/data`.

## Диалог и прогресс в кабинете

После «Создать материал» кабинет сразу открывает карточку задачи. Она показывает реальные этапы: очередь → подготовка текста → генерация изображения → сборка → согласование. Для ответа или уточнения генерация изображения не запускается. Публикация требует отдельного одобрения.

Если AI запросил детали, вопрос появляется в «Диалог с AI», под ним — «Ваш ответ на уточнение». Нажмите «Ответить и продолжить»: задача продолжится с тем же ID, исходными фото, форматом и настройками бренда. История сообщений сохраняется после перезапуска. Повторная отправка устаревшего ответа не запускает вторую генерацию. В списке «Ваши задачи» доступны предыдущие диалоги, готовые результаты и повтор после ошибки.

## Фотографии и формат

Сначала в «Компания» загрузите логотип, примеры изображений и при необходимости задайте эмодзи-пак. Сохраните настройки.

В кабинете добавьте снимки кнопкой «Свои фотографии», выберите формат и опишите задачу. Для замены визуала откройте готовый материал → «Добавить свои фото» или выберите другие пропорции → «Доработать». Выберите «Только изображение», чтобы сохранить текст. Режим «Только текст» сохраняет существующую картинку без обращения к image-модели.

В Telegram сначала при необходимости выберите формат командой, затем отправьте фото/альбом с заданием в подписи. Можно сначала отправить фотографии, потом задачу отдельным сообщением. Для существующего поста сначала нажмите «Доработать», затем отправьте фотографии с описанием изменений. /cancel отменяет незавершённую загрузку или доработку.

Оригиналы хранятся в `/data/uploads`, доступны только участникам соответствующей компании и не публикуются как отдельные файлы. Генератор получает загруженные для этой компании/задачи примеры стиля, отдельно оригинальный логотип и все прикреплённые фотографии как входы image-edit. Роли входов явно разделены: референсы задают стиль, логотип задаёт фирменный знак, исходные фото задают реальных героев и событие. Модель должна сохранять узнаваемость человека; результат всё равно требует визуального согласования. Если нативный размер image-модели отличается от выбранного, экспорт сохраняет полную композицию с мягким продолжением фона, без обрезки текста и искажения пропорций. Логотипы и референсы хранятся в runtime-данных, а не выбираются из жёстко заданного каталога. Для переноса на сервер нужны весь том `/data` (включая `uploads` и `media`) и сохранённые настройки.

## Надёжность и ограничения MVP

Данные хранятся в `/data/state.json`: один процесс Go с mutex, атомарная запись через временный файл, fsync и rename. Объём рассчитан на демонстрацию; горизонтальное масштабирование и несколько backend-реплик **не поддерживаются**. Для продукта нужна PostgreSQL и транзакционный outbox.

Telegram Bot API не поддерживает idempotency key публикации. Поэтому при таймауте/перезапуске в момент отправки пост переходит в «Проверьте канал», автоматически не отправляется повторно. Это предотвращает слепые повторы, но требует ручной сверки канала.

Очередь AI обрабатывается последовательно. Текст ограничен 150 секундами, отдельная генерация изображения — 5 минутами, общий процесс — 8 минутами. Для нового поста выполняются два вызова Codex, а для доработки только текста — один. Изображения используют тот же аккаунт и его лимиты; отдельного API-ключа нет. При недоступности image generation показывается ошибка с возможностью повтора. Описание картинки не выдаётся за готовое изображение. Регулярная задача создаёт черновик и требует нового одобрения. После простоя выполняется один пропущенный запуск, без шквала накопленных задач.

Фирменные Telegram-эмодзи восстанавливаются из пересланных сообщений с точными UTF-16 offsets. Telegram разрешает их ботам с дополнительным именем Fragment, а также в личных/групповых чатах при Premium у владельца бота. В режиме выбранного пака при отказе Telegram отправка завершается ошибкой без замены на стандартные эмодзи. Для режима «из пересланных примеров» при явном отказе API сохранён прежний стандартный эквивалент. Сетевые ошибки не приводят к слепому повтору публикации.

Для создания компании с готовым редакционным профилем откройте «Новая компания» → «Редакционный профиль». Визуальный интерфейс кабинета нейтрален; цвета и шрифты сохранены. Оригинальные материалы используются в создаваемых публикациях. В контейнере BRAND_ASSETS указывает на `/app/frontend/dist/assets/salavat`; перенос runtime-данных сохраняет загруженные примеры.

История хранится раздельно по компаниям (до 40 последних сообщений в контексте, полный диалог задачи сохраняется отдельно). Краткое описание — до 50 КБ, включённые документы передаются в контекст в пределах 100 тысяч знаков. RAG, OCR сканов и неограниченный обход сайтов не реализованы. Аналитика и обращения используют фактические импорты и доступные события; VK/MAX подготовлены без проверки реальных API по указанию заказчика. Получение message_id и ссылки подтверждает доставку, а не охват.

Доступ к ChatGPT зависит от тарифного плана, доступности аккаунта и его лимитов. Подтверждённая авторизация Codex не означает доступ ко всем инструментам веб-версии ChatGPT. Секреты `.env` и auth-кэш Codex не входят в Git.

## Расход подписки и ограничения

По уточнению заказчика сейчас учитывается потребление подписки, а денежный бюджет и серверное развёртывание отложены. Раздел «Лимиты и доступы» получает реальные окна лимитов через `codex app-server` → `account/rateLimits/read`: процент использования, длительность окна, время сброса и время снимка. Снимок обновляется автоматически раз в две минуты и вручную. Это общий лимит аккаунта, включая другие приложения; он не приписывается отдельной компании.

Каждый вызов приложения сохраняет компанию, задачу, версию, этап «текст / изображение», исполнителя, время и исход. Если Codex вернул `turn.completed.usage`, сохраняются реальные входные, выходные и кэшированные токены. Кэш уже входит во входные токены и повторно не прибавляется. Без статистики расход помечается неизвестным, а не нулевым. Учёт начинается с установки этой версии; прежние расходы не восстановлены. Статистика токенов CLI не является отдельным счётчиком кредитов image generation. Пересчитывать токены в процент подписки без данных провайдера нельзя.

Календарный месяц учёта начинается по UTC. Для компании доступны месячные ограничения числа AI-вызовов и изображений, порог токенов DeepSeek/Gemini/Ollama и порог расхода подписки ChatGPT. 0 отключает соответствующее ограничение. Перед каждым вызовом квота проверяется и попытка резервируется в журнале; параллельные запросы не обходят лимит числа вызовов. При включённом токен-пороге неизвестный расход других моделей блокирует их следующие вызовы. При контроле процента подписки устаревший более чем на пять минут или недоступный снимок также блокирует новые вызовы. Уже начавшийся вызов может перейти порог: это ограничение запуска, не жёсткий лимит токенов ответа у провайдера. Пауза компании и общая пауза останавливают новые AI-вызовы.

Нагрузочная модель месяца: 30 новых постов + 10 доработок только текста + 5 полных доработок = 45 текстовых и 35 графических вызовов, всего 80. Это расчёт числа операций, не обещание, что они поместятся в конкретную подписку. Денежная формула для последующей оценки: (ВМ + подписка + дополнительные оплаченные кредиты + хранение/резервные копии) / число обслуживаемых компаний. Фактические цены не предоставлены; числовая денежная оценка не выдаётся за измеренную.

## Подключение новой компании без программирования

1. Напишите боту `/start` и откройте кабинет. Доступ системного администратора выдаётся действующим администратором в «Лимиты и доступы» по числовому Telegram ID.
2. Нажмите «Компания» → «+ Компания». Введите название и сохраните профиль. В «О компании» укажите подтверждённые факты, аудиторию и тон. Редакционный профиль САЛАВАТСТЕКЛО необязателен для других клиентов.
3. В «Материалы о компании» загрузите PDF/DOCX/TXT/MD и добавьте нужные страницы сайта. Просмотрите извлечённый текст, исключите устаревшие источники переключателем «Учитывать».
4. Добавьте оригинальный логотип, визуальные примеры и пожелания. При необходимости укажите ссылку на Telegram-эмодзи-пак. Сохраните настройки.
5. Для Telegram добавьте бота администратором тестового канала с правом публикации. Укажите `@username` или числовой ID канала в профиле. Приложение проверяет права пользователя и бота.
6. В поле участников добавьте числовые Telegram ID сотрудников и сохраните. На вкладке «Правила и лимиты» назначьте согласующих, необходимое число одобрений, запрет одобрения автором и обязательную проверку фактов/визуала. Согласующие должны иметь доступ к компании. Изменение правил или площадки отменяет прежние одобрения; отозванный доступ не позволяет согласовать материал.
7. Настройте лимиты компании. Общий расход подписки и журнал вызовов доступны в «Лимиты и доступы». Для нового аккаунта нажмите «Подключить или сменить аккаунт» и самостоятельно завершите вход на официальной странице OpenAI с одноразовым кодом. Новый профиль принадлежит приложению; пароль приложение не получает. Существующий вход используется автоматически, пока отдельный профиль не выбран.
8. Создайте материал через Telegram или кабинет. Выберите площадку, фотографии и соотношение сторон. Проверьте результат и замечания проверки, при необходимости верните на доработку. Доработка отменяет прежние одобрения.
9. Для регулярных публикаций откройте «Расписание», выберите площадку и задачу. Ежедневно задаётся время, еженедельно — день и время, всё по МСК. Подготовка начинается за 15 минут. Согласуйте материал до времени публикации. Без согласования он не выйдет.
10. В «Маркетинг» подготовьте стратегию и утвердите её. Утверждённая стратегия учитывается в следующих публикациях. Темы и контент-план можно превратить в задачу на пост отдельной кнопкой. Сценарий видео сохраняется с раскадровкой, репликами, титрами и списком съёмок; готовый видеоролик не имитируется.

## Маркетинг и аналитика · меню ☰

- «Маркетинг»: версии стратегии, темы, контент-план, анализ конкурентов, сценарии коротких видео, отчёты и свои навыки. Результаты сохраняются отдельно от публикаций и скачиваются. В Telegram доступны `/strategy`, `/topics`, `/plan`, `/video`, `/report`, `/competitors`, а также соответствующие задачи обычным языком.
- Анализируются посты Telegram-каналов. Подборка: [Авиасейлс](https://t.me/aviasales), [DNative](https://t.me/dnative), [Русский маркетинг](https://t.me/smmrus), [Топор Live](https://t.me/toporlive). Можно добавить любой публичный канал по @имени/ссылке. Сбор — до трёх последних страниц публичного предпросмотра, а не полная история. Для закрытых каналов — JSON-экспорт Telegram Desktop. Сохраняются даты, тексты, ссылки и доступные счётчики. Платные звёзды исключаются из реакций, округления отмечаются ≈. Прочерк означает отсутствие данных. Рейтинг показывает реальные реакции; AI сравнивает результаты внутри каждого канала с его средним уровнем и отделяет популярность от свежести. Каналы являются референсами, а не источником фактов о компании. Сведения с сайта компании по-прежнему загружаются в «Компания → Профиль».

- Автономный маркетинг включается в правилах компании: ежедневные темы, еженедельная актуализация стратегии, еженедельный отчёт. Повторные задания одного типа не накапливаются, пока предыдущее выполняется. Новая стратегия остаётся черновиком до утверждения; автоматизация не разрешает публикации.
- «Аналитика»: только число опубликованных через приложение постов, реакции и комментарии. Период фильтрует дату публикации; счётчики — последние доступные на конец периода. Источники: события Telegram, публичная лента, ручной ввод или CSV. Снимки одного поста не суммируются. Сумма при неполном покрытии помечена числом постов с данными. Наблюдаемые комментарии считаются с момента подключения бота; это не восстановленная полная история.
- CSV использует `post_id,date,reactions,comments`, разделитель — запятая, UTF-8. Числа накопительные на дату снимка; пусто — не измерено. ID постов доступны в списке выбора для ручного ввода и JSON-экспорте аналитики.
- Проверка поста показывает неизвестные числа, заглушки и чек-лист визуала/фактов. Сопоставление чисел не доказывает актуальность утверждения. При включённом правиле согласующий должен явно подтвердить проверку текущей версии. Автоматическая проверка не заменяет редактора.

## ВКонтакте и MAX — подключение подготовлено, проверка отложена

По указанию заказчика интеграции реализованы без токенов и без тестирования API. До подключения статус остаётся «Токен не подключён / Подключение не проверено». Наличие кода не является подтверждением успешной отправки на этих площадках.

В «Компания → Площадки» укажите числовой ID сообщества VK или канала MAX, токен, разрешение публикации и отдельно мониторинг. Пустое поле токена сохраняет существующий секрет; кнопка отключения удаляет его и выключает подключение. Секреты шифруются AES-GCM в отдельном файле данных с ключом установки и правами 0600; они не попадают в публичный API, Git или промпт AI. Для резервного копирования нужен защищённый полный том данных.

Предусмотрены загрузка изображений, отправка согласованного текста с изображением, получение доступной статистики, комментариев и отправка согласованных ответов. Для VK нужны права стены, фото и комментариев; для MAX — права администратора канала, публикации и чтения комментариев. Мониторинг ограничен последними 50 публикациями приложения; VK — до 500 комментариев на пост, MAX — до 100. Доступность конкретных счётчиков зависит от ответа API. Custom emoji Telegram не переносится в другие сети: там используется допустимая Unicode-палитра выбранного пака.

Основание реализации: [официальная схема VK API](https://github.com/VKCOM/vk-api-schema), [MAX: сообщения](https://dev.max.ru/docs-api/methods/POST/messages), [MAX: медиа](https://dev.max.ru/docs-api/use-cases/sending-messages/media/), [MAX: комментарии](https://dev.max.ru/docs-api/methods/GET/messages/-messageId-/comments/). MAX использует `platform-api2.max.ru`; проверка TLS не отключается. Перед эксплуатацией обязательна отдельная проверка с реальными доступами в тестовых сообществах.

VK/MAX в протоколе отмечаются непроверенными.

## Доработки для коммерческой эксплуатации

3. Перейти с JSON-файла и единственного процесса на транзакционное хранилище и очередь для нескольких экземпляров, больших объёмов и изоляции ресурсов компаний.

## Исполнители текста и расход

В меню ☰ → «Лимиты и доступы» доступны ChatGPT, DeepSeek, Gemini и Ollama. Для DeepSeek/Gemini можно сохранить модель и позже добавить API-ключ; без ключа активация в интерфейсе недоступна, сервер также блокирует вызов. Ключи шифруются AES-GCM в том же защищённом хранилище установки, что и ключи площадок; в API возвращается только признак сохранения. Сохранение не делает проверочный вызов. Активировать исполнителя текста нужно отдельной кнопкой. Изображения продолжают создаваться через ChatGPT/Codex.

ChatGPT показывается в процентах реальных окон подписки всего аккаунта. Токены не переводятся в проценты и не распределяются по компаниям. DeepSeek/Gemini используют официальные OpenAI-совместимые API: [DeepSeek](https://api-docs.deepseek.com/), [Gemini](https://ai.google.dev/gemini-api/docs/openai). Их статистика и статистика Ollama учитываются по входным и выходным токенам из ответа. Кэш входит во входные токены, неизвестная статистика отмечается отдельно. API-ключи пока не добавлены, реальные вызовы этих провайдеров не проверялись по указанию пользователя.

Порог процента применяется только к ChatGPT, включая изображения. Месячный токен-порог компании применяется к сумме DeepSeek/Gemini/Ollama. Общая пауза и лимит числа вызовов действуют для всех исполнителей. Денежная стоимость не рассчитывается.

В нижней навигации сохранены «Обзор», «Публикации», «Расписание», «Компания», «Компании». Маркетинг, аналитика, лимиты и инструкция находятся в меню ☰. Раздел обращений и отправка ответов отключены.

Для этой редакции выполнены сборки Go и Vue и визуальный просмотр интерфейса. Новые проверки API/генераций и автоматические тесты не запускались по указанию пользователя; acceptance.json относится к предыдущей редакции.

## Вход ChatGPT и удалённый сервер Ollama

Новая установка не авторизована в ChatGPT. Вход выполняется кнопкой «Войти в ChatGPT» в админке, через одноразовый код OpenAI. Профиль хранится только в `DATA_DIR/codex-profile`: системный аккаунт Codex и системное хранилище учётных данных не используются. После успешного входа сессия приложения сохраняется между перезапусками; «Выйти из аккаунта» отключает её. До входа новые вызовы ChatGPT и получение лимитов заблокированы. Копировать авторизацию компьютера в приложение не нужно.

Для Ollama на отдельном сервере в админке указываются:

- Адрес API сервера, доступный с машины приложения: `https://ollama.example.ru` или `http://IP:11434`. Порт указывается в URL. Суффикс `/api/generate` приложение добавляет само; введённый `/api` тоже распознаётся.
- Точное имя модели, установленной на том сервере.
- Авторизация: «Без авторизации» для прямого собственного API либо «Bearer · ключ доступа» для шлюза с таким способом защиты. В режиме Bearer ключ хранится зашифрованным и передаётся только этому серверу; переходы HTTP с ключом запрещены.

На стороне сервера Ollama должна слушать сетевой адрес, а нужный порт должен быть доступен приложению. Это настраивается через `OLLAMA_HOST` и сетевые правила самого сервера. Локальный `127.0.0.1` не является адресом другого сервера. В приложении нет автоматического перехода на localhost при незаполненном адресе. Официальные сведения: [сетевой доступ Ollama](https://docs.ollama.com/faq#how-can-i-expose-ollama-on-my-network), [авторизация API](https://docs.ollama.com/api/authentication).
